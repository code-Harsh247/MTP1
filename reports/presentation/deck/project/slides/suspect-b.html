Catastrophic Forgetting in Continual Ear Recognition

(60 seconds) Suspect B: maybe the memory is there, but drowned out. To test it, I ran an oracle — a deliberate cheat. At the end of task 1, copies 2 and 3 are frozen at exactly the task-1 weights, so two of the three copies hold a perfect memory of task 1. Task-1 forgetting does drop, from 0.445 to 0.272, but most of the loss remains. Here is the giveaway: if I use a frozen copy alone, it still scores 0.79 on task 1. The whole model scores only 0.58. The memory is intact, but the output is a weighted sum, so the moving copy, together with the neck and the backbone, overrides it. On the right: inside each CMS layer, the three copies are mixed, and by the end the fast copy has the biggest say, 41%, against 30% for each frozen copy. Together with the rest of the network, which has also changed, it outvotes the frozen copies, and group 1 comes out at only 0.58.
